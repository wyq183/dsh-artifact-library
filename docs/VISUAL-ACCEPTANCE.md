## 七、⚠️「预期如此，别当 bug 报」清单

**这几条现在看起来像问题，但都是刻意设计或已知限制**：

| 现象 | 为什么是预期 |
|:---|:---|
| 设置里改了「**面板宽度**」，宽度**不变** | **已知未接线**：只存数值，宽度生效等有验收手段再做（lead 决定，避免动宿主布局） |
| 顶部**没有**「改动」页签 | 正常：`/session-changes` 返回 404 时**整个入口会被摘掉**（不显示空面板）。**只有真的跑过一轮会改文件的对话**，它才会出现 |
| 拖入文件提示「**拿不到真实路径**」 | 浏览器安全限制；只有 Electron 能拿到路径。这是**诚实提示**，不是失败 |
| 文件视图说「**搜索需要先启动文件索引**」 | 索引默认没启动（不索引全盘，保护隐私）。点「启动文件索引」或改用「目录」视图 |
| 「最近…」下拉**一开始是空的** | 需要**逛过**目录才会记录 |
| 只读「打开/复制」类按钮点了没视觉反馈 | 会在面板底部**弹一句提示**（toast）；若连提示都没有才是 bug |
| 浅色/深色主题下颜色不同 | 全部走官方 token，**跟随主题是预期**；但若出现**刺眼的白块/黑块**（不跟随主题）就报 |

## 附一：**机器已保证**的部分（✅ 这些**不用**你看）

由 12 个测试文件 / 323 条断言锁住。**列出来是为了让你知道「这些我们确实管住了」，而不是让你去核对。**

| 机器保证的事 | 为什么人眼验不了 |
|:---|:---|
| 颜色只用官方 token（禁 hex / 禁自造 `--alf-*` 变量）、无 emoji 当图标 | 是不是「官方色」人眼分辨不出，但机器能逐个比对 |
| 行高常量 = 24/32/44；排序是自然序（file2 在 file10 前） | 数字越界人眼看不出 |
| 无障碍属性齐全（`aria-label` / `role=grid\|row` / `aria-rowcount` / `aria-rowindex` / `aria-selected`） | 读屏语义**看不见**，只能静态验 |
| 设置面板**照 schema 渲染**（不写死键）；每个客户端生效键**都有渲染消费点** | 「有没有接线」是结构事实，肉眼只会看到「改了没反应」——那已经是结果了 |
| 「重复登记」**不会**被错误放进撤销名单（破坏性操作） | 这是数据安全的**反例**断言，肉眼几乎不可能发现 |
| 各端点 URL 拼接与 `encodeURIComponent` | 编码细节肉眼不可见 |
| 空状态**不得**用浮层/弹窗（引导必须长在空状态里） | 「有没有浮层」机器能扫，人只会觉得「有点打扰」 |
| 图标表与 `lib/icons.js` 无漂移（指纹比对） | 图标画错一点人眼很难发现 |

> 这几类**如果**你在真机上看到不对劲（比如「图标颜色明显刺眼」），**照样报** ——
> 断言管的是「有没有这条规则」，管不了「这条规则好不好看」。

## 附三：**语义搜索「搜得准不准」的反例集**（照做即可，不用自己想）

> 来源：ui-tester（2026-09-30 夜）。起因是 host-dev 挖出的一个真 bug：
> `searchSemantic` 的中文 2-gram 实现**把英文也切了** —— 查询 `q7z9w3x5qq-no-such-token` 竟命中 1 条
> （`token` 被切成 `to/ok/ke/en`，而 **`to` 藏在几乎每条路径的 `Administrator` 里**），`matched:["to"]`、score=2。
>
> **那个 bug 不是任何门禁发现的** —— 是**有人构造了一个怪查询**才发现的。
> **这和我们写判据时用的 bite-test 是同一个方法：不构造反例，就读不出「过宽」。**

**为什么要有这一节**：语义搜索的质量**没有自动化门禁能覆盖**（它保证的是「没静默降级 / 没复用关键词 / 两分支不混」，
**不保证「搜得准」**）。所以把它写成**三个具体反例**，让人照着跑 —— 比「随便搜搜看」有用得多。

| # | 查询 | 应该发生 | 如果不对，说明什么 |
|:-:|:---|:---|:---|
| **S1** | 一个**无意义的长 token**（如 `q7z9w3x5qq-no-such-token`）| **0 命中**（或只有极低分、且理由清楚）| **还没有** —— 若命中一堆，说明**召回过宽**（同一个 bug 的回潮）|
| **S2** | 一段**纯中文、无空格**的短语（从某条记录的标题里摘）| **命中那条记录**，且 `matched` 指向标题 | 若不命中，说明**中文 2-gram 被改坏了**（反向）|
| **S3** | 把某条记录标题**只改一个字母**的近似词 | **不应给它满分**；满分应该留给真正相同的词 | 若满分，说明**打分区分度不够**（低分噪声与真命中分不开）|

**⭐ 怎么算「通过」**：三条都对 → 语义搜索**在召回的宽严上是健康的**。
**⭐ 如果 S1 又出现噪声** → 优先怀疑**分词/2-gram**那条路径（今天刚修过一次）。
