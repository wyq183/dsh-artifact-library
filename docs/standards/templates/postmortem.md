> 模板。**复制到 `docs/postmortem/YYYY-MM-DD-<slug>.md`** 再填。
> 门槛：**这个 bug 隐蔽、系统、重新发现代价高** 时才写。
> 一次性的手误不用写；**"测试全绿但真机不对"这类必须写。**

## 一、执行摘要

**三句话**：发生了什么 / 根因是什么 / 现在靠什么防住。

---

## 二、时间线

| 时刻 | 发生了什么 |
|:--|:--|
| | 引入 |
| | 上线 |
| | **本可以被发现的机会**（哪一步本该抓住它？为什么没有？） |
| | 发现 |
| | 修复 |

⭐ **"本可以被发现的机会"这一行是复盘的核心。**
它把"运气不好"变成"流程有个洞"。

---

## 三、根因

**具体到机制**，不是"代码写错了"。

⚠️ 追问至少三层：
1. 直接原因是什么？
2. **为什么这个原因能存在**（哪道闸门本该拦住它）？
3. **为什么那道闸门没拦住**（它根本不存在？还是它在错的层级？）

---

## 四、⭐ 为什么它没被抓住（**这一节最重要**）

| 本该抓住它的东西 | 为什么没抓住 |
|:--|:--|
| 单元测试 | |
| 静态检查 / lint | |
| 真机验证 | |
| 代码评审 | |
| **测试全绿** | ⚠️ 如果答案是"测试确实全绿"，**说清测试床为什么看不见它** |

⚠️ **区分"没有闸门"和"闸门在错的层级"** —— 后者更危险，因为**你会以为有保护**。

## 六、护栏（**防的是什么，不是"加了个测试"**）

| 护栏 | 在哪 | **验过它会红吗** |
|:--|:--|:--|
| | | ⚠️ **没验过的护栏不算护栏** |

⚠️ **如果护栏是"以后要注意"，那它不是护栏** —— 那只是愿望。
要么做成 `[机器]`，要么做成有明确检查项的 `[清单]`。

---

## 七、推广：这是**一类**还是**一次**？

| 问题 | 答 |
|:--|:--|
| 同类问题还可能出现在哪？ | |
| 现有的其他守卫里，有没有**同族**的空转/过宽？ | |
| 本仓库的规范该补哪一条？ | |

⭐ **本仓库实证**：三个 UI bug 是**同族**（层级 / 位置 / 尺寸），
都是"逻辑测试全绿 + 真机不对"。
⇒ **发现一次要去找同族，不要只修这一个。**
