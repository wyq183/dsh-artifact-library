## 二、P2 能力清单（建议）

### A. 目录树视图（真正像文件管理器）

- 左树右列表：以工作区为根 + 可切换到「已登记目录」
- 树节点按需展开（复用 Everything 的 `parent:` / `path:` 查询，而不是逐层读盘）
- 排序、隐藏文件开关、当前文件高亮
- **与官方文件页的差别**：官方只能列当前会话的工作区；我们可跨工作区、可搜索、有产物语义

### B. 主动纳管（这是依琪最强调的一条）

1. **会话工作区自动纳入**
   - 订阅会话事件（`session/event`）→ 新会话出现 → 取其 cwd → 加入索引范围
   - 范围变化 → 触发增量重建（现在会自动重启实例，但要让它「只加到新目录」而不是全量重建）
2. **变更监听**
   - Everything 自带 `folder_monitor_changes=1`，文件变化实时进索引 —— 这一块**免费得到**
   - 但我们还要「产物库层面」的联动：工作区里新增的、看起来像产出的文件（扩展名/大小/路径特征）自动进库（现已有的 autoCollect 只管会话工具写过的文件）
3. **内容感知（可选，成本高）**
   - 现在只能按文件名/路径搜
   - 若要做内容检索：① 对文本类文件建轻量倒排索引 ② 或接 Everything 1.5 的 content indexing
   - **建议先不做** —— 需求没提，且会显著增加复杂度与磁盘占用

### C. 文件与产物的双向联动

| 方向 | 交互 |
|:---|:---|
| 文件 → 产物 | 树上右键「登记为产物」（P1 的搜索列表已有单条登记） |
| 产物 → 文件 | 产物卡片「在文件树中定位」 |
| 批量 | 树/列表多选 → 批量登记 / 批量打标签 |

### D. 文件管理器该有的操作

- 打开（用系统默认程序）
- 在资源管理器中显示（已有 `/open` 端点，但只对已登记产物生效 → P2 要扩到任意路径）
- 复制路径 / 重命名 / 删除（**删除要谨慎**，建议只做「移到回收站」且需二次确认）
- 拖拽到输入框（@ 文件）—— 对齐官方能力

### E. 自动整理分类（继承 + 增强）

- 现有：AI 精化（补摘要/标签/项目）
- P2 增强：
  - 按目录结构自动推断项目（`C:\...\项目A\...` → project=项目A）
  - 按扩展名自动分类型（已有）
  - 空目录/僵尸目录识别（已有 cleanup 的一部分）

## 三、技术方案要点

### 1. 目录树怎么取

**不要**逐层 `fs.readdir`（慢、且官方已有这能力）。
**用 Everything 查询**：`parent:"C:\path"` 或 `path:"C:\path"` + `depth:1`（1.5 支持 depth）。

好处：与搜索结果同一套引擎，排序/过滤语法一致，天然跨工作区。

### 2. 范围增量更新

现状：范围变化 → 重写 ini → **重启实例**（全量重建索引）。

P2 改进：
- Everything 1.5 支持**运行时添加/删除 folder index**（需要确认 API 形态：可能通过 IPC 或 HTTP 插件）
- 若不可行，退而求其次：**把范围拆成稳定集 + 动态集**，动态集用「查询时过滤」而不是「索引时白名单」
  - 即：索引范围固定为较大的父目录（如用户目录），查询时用 `path:` 限制到当前工作区
  - ⚠️ 但这**扩大了索引范围**，与「隐私边界」冲突 → **需要依琪拍板**

### 3. 主动纳管的触发点

- `ctx.on('session/event')`：会话创建 → 取 cwd（`ctx.sessionController` 或 `ctx.workspaceController`）
- 定时（每 N 分钟）+ 事件驱动（范围变化时）双保险

### 4. 状态与持久化

- 索引范围快照：`~/.dsh/artifact-library/index/scope.json`
- 引擎状态：`engine-state.json`（已有）

## 七、✅ 前置验证结论（2026-09-30 凌晨实测，已完成）

### 1. 目录树查询：用 `-parent` **选项**，不是搜索语法

| 试法 | 结果 |
|:---|:---|
| `parent:"<dir>"`（当搜索串用） | ❌ 返回空 |
| `path:"<dir>" depth:1` | ❌ 返回空 |
| **`es.exe -parent <dir>`** | ✅ **精确返回直接子项**（不含更深层） |

**区分目录与文件** —— Everything 的结果里**没有类型字段**，用 DOS 属性开关：

| 命令 | 结果 |
|:---|:---|
| `-parent <dir> /ad` | ✅ 只列**目录** |
| `-parent <dir> /a-d` | ✅ 只列**文件** |

⚠️ **目录结果会带尾部分隔符**（`…\sub\`）—— 实现时要么规范化，要么加 `-no-folder-append-path-separator`。

### 2. 编码：export 通道再次确认无误

同一个文件，PowerShell 里显示 `������.txt`，而 **export 出的 JSON 是 `中文名.txt`** ✅
（再次印证 P1 的决策：**永远走 `-export-json`，不要读 stdout**。）

### 3. 会话 cwd 从哪来

官方 `dsh-api-session-controller` 的类型定义里反复出现：

- **`agent.session.header.cwd`** —— 会话 header 上挂着 cwd
- `observation.header.cwd`

**结论**：P2 主动纳管从 `session.header.cwd` 取工作区路径，取不到再退回 `session.cwd`（防御式）。

### 4. 索引范围动态更新的结论

ES **没有**「运行时增删 folder index」的命令行选项（只有 `-reindex`，且它只重扫已配置的目录）。
所以 P2 采用：

> **范围变化 → 防抖攒批（如 30 秒）→ 空闲时（无查询在跑）重启实例**
> 重启期间查询返回「索引重建中」而不是报错。

这是 P1 已有机制的平滑化，**不改变隐私边界**（不靠"索引大范围再查询收窄"那种取巧做法）。

### 5. 顺带确认

- `-reindex` 会阻塞到索引完成（可用于「用户手动强制重建」按钮）
- `-get-folder-size <dir>` 存在 —— 将来做「目录体积」显示可用
- `-instance <name>` / `-ipc1|2|3` 可用（实例隔离与兼容性兜底）
