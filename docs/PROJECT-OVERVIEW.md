> 一份给外部评审者看的完整介绍。写于 2026-10-22。

## 一、一句话说明

**DSH（DeepSeek Harness）的客户端插件**，把 AI 会话里产出的文件、参考素材、项目经验统一登记、整理、检索。

- 用户：单人（作者本人），本机使用
- 形态：DSH 插件（`@dsh-external/dsh-artifact-library`）
- 规模：470 条真实数据 / 47 个测试文件 / 约 1.1 万行代码
- 仓库：`git@github.com:wyq183/dsh-artifact-library.git`（私有）

---

## 二、它解决什么问题

### 痛点来源

用户用 DSH 做各种项目（做视频、写文档、改手机固件、研究模型部署）。**AI 生成的产物散落在各处**：

- 会话结束后，产出文件在哪？叫什么？
- 上次那个「验证对照图」放哪了？
- 这个项目踩过哪些坑？下次怎么避开？

Windows 搜索能找到文件，但**找不到"这是干什么的"**。

### 三个核心能力

| 能力 | 说明 |
|:--|:--|
| **登记** | 文件进库时自动/手动补上：标题、摘要、项目、类型、标签 |
| **整理** | 目录树、项目分组、标签治理、重复检测、僵尸项目清理 |
| **检索** | 关键词搜索 + 语义搜索 + 按项目/类型/标签多维筛选 |

### 正在做的第三件事：知识沉淀

用户明确要求：**把每个项目的经验、踩过的坑，存成可检索的知识条目**（不是文件，是短条目）。

这一块**尚未实现**，是本轮讨论的产物。

## 三、架构

### 进程与分层

```
DSH 宿主（Electron 主进程）
  │
  ├─ lib/index.js        插件入口：注册 agent 工具 + HTTP 路由 + 侧栏 UI
  │
  ├─ lib/tools.js        17 个 agent 工具（artifact_list / artifact_find / ...）
  ├─ lib/http.js         37 个 HTTP 端点（/ext/artifacts/*）
  ├─ lib/client.js       侧栏 UI（React，无构建步骤，手写 createElement）
  │
  ├─ lib/store.js        数据层（JSON 文件 + 内存索引）
  ├─ lib/index/          Everything 索引集成（14 个文件）
  ├─ lib/tags.js         标签统计/去重/合并
  ├─ lib/project-merge.js 项目名合并（带撤销）
  └─ ui/index.html       独立管理页（单文件，约 3400 行内联 JS）
```

### 数据存储

**单文件 JSON**：`~/.dsh/artifact-library/artifacts.json`（当前约 3.2 MB）

记录结构（关键字段）：

```js
{
  id, kind,              // deliverable（产出）/ reference（参考素材）
  path, filename,        // 磁盘位置
  size_bytes, mtime,
  title, summary,        // AI 精化填的
  project, deliverable,  // 归属
  artifact_type,         // document / image / video / code / ...
  tags: [],
  folder: "",            // 逻辑归类（2026-10-20 新增）
  contentIndex,          // 正文前 8000 字符（用于搜索）
  needsRefine,           // 缺摘要/标签/项目
  references: [],        // 产出↔资料关联
  status, trashed_at
}
```

### 两个界面

| 界面 | 位置 | 技术 |
|:--|:--|:--|
| **侧栏** | DSH 右栏（620px 宽） | React，`lib/client.js`（303 KB） |
| **管理页** | `/ext/artifact-library/` | 单文件 HTML + 内联 JS（3400 行） |

⚠️ **两个界面各写一套 UI**，同一功能实现两遍（如标签芯片、多选下拉）。这是当前最大的架构债。

## 四、功能清单

### 4.1 登记与精化

- **自动采集**：会话结束钩子，自动登记产出的文件
- **手动登记**：管理页「＋ 登记产物」
- **文件夹导入**：整目录导入（含正文索引）
- **AI 精化**：缺摘要/标签/项目的条目，交给 AI 会话补全
  - 设置里可指定精化用的模型
  - `needsRefine` 标记 + 优先队列

### 4.2 整理

| 功能 | 说明 |
|:--|:--|
| **目录树** | 按 `folder` 逻辑分组，可嵌套，支持移动/删除/撤销 |
| **项目** | 按 `project` 字段分组（2026-10-22 刚改成"项目文件夹 → 点进去看文件"） |
| **标签治理** | 受管标签（带颜色/字重）+ 自由标签；重复检测、批量合并 |
| **项目合并** | 相似项目名合并，可撤销 |
| **整理建议** | 重复记录 / 文件缺失 / 待精化 / 僵尸项目 |
| **回收站** | 软删除 + 恢复 + 彻底删除 |

### 4.3 检索

- **关键词搜索**：标题/摘要/正文/文件名（服务端，走 `contentIndex`）
- **语义搜索**：一句话描述找东西（纯内存打分，非向量）
- **多维筛选**：类别 / 类型 / 项目 / 标签（**多选，维度内 OR、维度间 AND**）
- **全盘搜索**：Everything 索引语法（`ext:md`、`dm:today`、`size:>10mb`）

### 4.4 视图与分类（2026-10-22 重构后）

**分类（数据源）**：

```
📦 全部产物 | 📁 按项目 | 🕒 最近改动 | 🔍 全盘搜索
```

**视图（呈现方式）**：列表 / 卡片（四级尺寸：小 80 / 中 160 / 大 260 / 超大 400px）

## 五、技术要点（值得看的部分）

### 5.1 无构建的 React

`lib/client.js` 手写 `React.createElement`，不经过打包。原因：插件要能被 DSH 直接 `require`，加构建步骤会让安装变复杂。

代价：没有 JSX，代码冗长（303 KB）。

### 5.2 数据层的不变量

```js
// save() 是同步序列化 + 写盘
// 实测：0.5MB→16ms / 3.4MB→19ms / 29.1MB→73ms
```

为此做了 `deferSave`（批量导入时只进内存，最后落一次盘）。

### 5.3 安全边界

- **CSRF**：所有写操作要 `x-dsh-artifacts: 1` 头（自定义头会触发预检）
- **范围校验**：`assertInScope` 只放行索引范围内的路径
- **敏感路径拒绝**：凭据目录（`.ssh` / `.gnupg`）、系统目录
- **缩略图通道**：`/files/thumb` **只认图片**，不提供通用读盘能力

### 5.4 测试策略

47 个测试文件，**不依赖浏览器**（纯 Node + `vm` 模块求值）：

- 从源码里抠函数体，喂数据跑行为
- **反向对照**：故意造坏样本，确认判据能抓住
- **真实数据锚定**：某些断言用真库的实测数字（如"标签中位数 6"）

命令：`npm run check` = lint + 47 个测试 + 重复代码检测 + 文档新鲜度

## 九、给评审者的具体问题

1. **两套 UI 怎么收敛？** 侧栏是 React（无构建），管理页是原生 JS。合并成一套的可行路径是什么？考虑 DSH 插件的加载约束（不能有构建步骤）。

2. **四个分类维度怎么理清？** `project` / `folder` / `tags` / `artifact_type` 都在表达"分类"，用户已经反馈"按项目和全部产物毫无区别"。应该合并、还是明确分工？

3. **测试怎么从"字符串断言"升级到"行为测试"？** 现在 47 个测试里约 40 个是 `assert(/xxx/.test(sourceBody))`，能防"代码被误删"，但**防不住逻辑错**（本轮就出过：逻辑写了、测试过了、入口没接上）。

4. **单 JSON 存储的天花板在哪？** 470 条 3.2 MB，全量读写。到什么规模该换 SQLite？

5. **知识条目该不该和产物表合并？** 独立 `knowledge.json` vs 复用 `artifacts.json` 加 `kind: 'knowledge'`——各自代价？

## 十、附：关键设计决策（有据可查）

| 决策 | 理由 |
|:--|:--|
| 多选筛选在**前端**做 | 宿主 `store.list()` 只支持单值相等，无法下推 |
| `folder` 用**路径串**不用 id 树 | 移动 = 一次前缀替换；id 树要递归改，部分失败会断链 |
| 目录树**不存**，从记录现算 | 存树必然出现"树里有、记录没有"的不一致 |
| `refine` 保留单选 | 只有两个值，选两个等于不筛 |
| 卡片尺寸**高度+列宽一起变** | 只改高度 = 列数不变 = 看起来没放大（用户实测反馈） |
| 分类 ≠ 视图 | 分类换"看什么"，视图换"怎么看"（用户纠正的） |
| 删除目录要**两次确认** | 第一次说清后果，第二次**手打目录名**（连点两次 confirm 等于没确认） |
