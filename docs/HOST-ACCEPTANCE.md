| **M5** | 让 agent 调 `artifact_list`，同一个筛选条件跑两次：`limit=5` 与 `limit=50` | 两次头部**命中数一致**（例如都是「命中 22 条」），只是「返回第 X-Y 条」不同 | **两次命中数不一样**（比如 5 和 22）= 拿返回条数冒充命中数 | 🖥 |

> ⚠️ **I5 验完请把目录名改回来**，否则索引能力一直是坏的（这条只用于验证错误提示，不是常规操作）。
| I6 | Everything 缺失状态下调 `/files?q=xxx` 与 `/files/list?dir=…` | `/files?q=` 明确回「未就绪/缺失」的错误；**`/files/list` 仍然正常工作**（目录浏览不依赖索引） | 两者一起挂 = 目录浏览被索引拖下水（这轮特意解耦过） | 🖥 |

## 报告格式（照这个写，能省我们一轮往返）

```
【不过】M1 · 索引停止
操作：在大范围上 POST /files/start → 等 3 秒 → POST /files/stop → 每 2 秒 GET /files/status
看到：30 秒后 phase 仍是 "starting"，cancellable 仍为 true
期望：几秒内变成 "stopped"
补充：/files/status 全文（贴 JSON）+ 宿主日志最后 20 行
```

**三条经验**（今晚踩出来的，写进来免得下次再踩）：
1. **端口写 `{PORT}`，不要抄我的数字** —— 端口由运行时决定（用 `/ext/artifacts/ui-url` 拿）。
2. **别写行号** —— 今天已经证实行号会漂（`http.js:494` 已不再是 `/import`）。**报符号名/端点名**（如 `resolveIndexScope`、`/files/stop`）。
3. **别下绝对时间结论** —— 报「超过明显异常线还是怎样」+ 贴原始 JSON，比「应该 3 秒内」有用得多。
