# 已废弃的测试断言

> **这份文件的存在理由**：删掉的守卫**不能就这么消失** —— 否则下一个人看到
> 「主面板」这个词时会以为它还在，或者反过来，以为某条不变量从来没人守过。
>
> 每一条都记：**原来守什么 · 为什么不再适用 · 那条不变量现在谁守**。
>
> 最后一条尤其重要：**废弃 ≠ 不变量消失**。绝大多数情况是「功能搬了，守卫也该跟着搬」，
> 真·消失的只有少数。

---

## 背景：2026-10-14 档 1d

依琪拍板：

> 「**主区面板不要了，全部转到右侧栏**」·「**左边的都不要了**」

⇒ `lib/client.js` 删掉：

| 删了什么 | 行数 |
|:--|--:|
| 三个旧席位（`main` / `sidebar.panellist` / `sidebar.footer.action`）及其组件 | ~1 636 |
| 18 个只被它们引用的组件（`PanelInner` / `DirBrowser` / `SettingsPanel` / `CleanupView` / `FilesView` / `DetailDrawer` / `SemanticView` / `ImportPanel` / `ChangesView` / `renderCards` / `renderTable` …） | 3 838 |
| **合计** | **9 893 → 4 405 行** |

新形态：**右栏 tab**（`kind:"files"`，接管官方文件树）+ **HTTP 管理页**（低频功能）。
完整管理页入口**搬进了右栏头部**（那个「管理页」按钮）—— 否则用户没入口。

### 处置原则（依琪选的 B 方案：废弃 + 移植）

| 处置 | 含义 | 适用 |
|:--|:--|:--|
| **移植** | 不变量还成立，**换个主体继续守** | 越界引用 · 空态三态 · 骨架屏 · a11y |
| **废弃** | 守的东西**物理上不存在了**（没有替代品） | 主面板的渲染分支 · 抽屉交互 · 拖拽 |
| **删除** | 纯属旧写法的实现细节，**没有不变量** | 席位注册计数 · 旧 class 名 |

⚠️ **判据：先问「这条守的性质还在不在」，再决定处置。**
「主体没了」不等于「性质没了」—— `scope-leak` 就是最好的例子。

## 一、移植的（不变量还在，换了主体）

### 1.1 `scope-leak.test.mjs` —— 模块层 `ctx` 越界引用

| 项 | 内容 |
|:--|:--|
| **原判据** | `getCtx: function () { return hostCtx; }`（不许写回裸 `ctx`） |
| **原主体** | `PanelInner` 的 `getCtx` + 模块级 `hostCtx` |
| **为什么废** | `PanelInner` / `getCtx` / `nativePicker` 全删了；`hostCtx` 变成**只写不读**的死代码（也删了） |
| **性质** | 「**模块层函数引用了它没有的 `ctx`**」—— 一调用就 `ReferenceError`，还常被 `catch` 吞掉、**静默**退化成一句假话 |
| **新判据** | 「**形参里没有 `ctx` 的模块层函数，函数体不许出现裸 `ctx`**」 |
| **⚠️ 移植的关键** | 必须带「形参里没有」这个限定 —— `apply(ctx)` / `bootProbe(ctx)` / `registerAtSource(ctx)` 都拿它当形参，引用它合法。**我第一版漏了 ⇒ 三条误报**（同一类错误：判据写宽一点就开始冤枉好人） |
| **顺带** | 那条 `assert(true, '（这条永远通过，它只是文档）')` 改成**真断言**：验 `eslint.config.mjs` 里确实有 `js.configs.recommended`（`no-undef` 归它），并带反面对照 |

### 1.2 `tag-chip.test.mjs` —— 标签芯片接线

| 项 | 内容 |
|:--|:--|
| **原判据** | [F] 组守 `DetailDrawer` 的调用点 / `reloadManaged` / `reload` 里的 `managed: previous.managed`；[G] 组渲染 `DetailDrawer` |
| **原主体** | 主面板的详情抽屉 |
| **为什么废** | `DetailDrawer` 删了 ⇒ HOOK 里还导出它 ⇒ **`ReferenceError`（真 bug，测试直接崩）** |
| **性质** | ① 受管表 → `tagChips` 的接线真的通了；② 「**读不到**」与「**读到了但是空**」必须分得开；③ 列表重拉不许把 `managed` 弄丢 |
| **新主体** | **右栏预览**（`RightPanePreview`）—— `RightPaneBody` 拉 `/managed-tags` 一路传下去。**功能本身是活的**，只是换了地方渲染 |
| **新判据** | [G] 改渲染 `RightPanePreview`（5 条，全过）；[F] 改守新接线：调用点显式传 `surface:"chip"` + `managed:`（含反向对照 F1b）、`/managed-tags` 真的拉、**失败不许写成 `[]`**、**列表 effect 里不许出现 `setManaged`** |
| **⚠️ F5b 的教训** | 我第一版把「宽窗口」取成**往后** 1800 字符 —— 而受管 effect 在列表 effect **之前**（实测 -626/-344/-281）⇒ 方向反了 ⇒ 那条对照**空转**，被它自己当场抓住（「宽切片里居然也没有 setManaged ⇒ 前提不成立」）。改成往前取 900，并把**实测的相对位置写进注释**（位置一变就当场红） |

### 1.3 `persist-fail.test.mjs` G4 —— 撤销提示的统一渲染函数

| 项 | 内容 |
|:--|:--|
| **原判据** | 面板那侧有**统一渲染函数** `undoNotify`（不是每次调用各写一遍） |
| **为什么废** | `undoNotify` 随 `PanelInner` 一起删了 |
| **性质** | 「撤销提示只有**一处**渲染逻辑」—— 防止将来加撤销入口时各抄一遍 |
| **现状** | **右栏目前没有撤销入口**（管理页里有）。⇒ 断言改成：**若** `client.js` 里出现撤销提示，**必须**走统一函数 |

### 关于第 4 条（**2026-10-14 新增**）

删掉三个旧席位后，又**新暴露出一批孤儿**（原来被 `PanelInner` 引用着，面板一删就没人用了）：

```
 209 行  ViewControl        视图切换（列表/卡片/项目/文件/目录）
 208 行  Thumb              缩略图（自建端点 + 官方后备 + onError 回退 + 5MB 门槛）
  69 行  Badges             徽章
 107 行  renderCards        卡片视图渲染
 108 行  renderTable        表格视图渲染
  41 行  MERGE_CONFIDENCE_LABEL / 37 SEMANTIC_DEBOUNCE / 31 placeMenu …
 ─────
 997 行 / 49 个符号（占文件 22%）
```

**⚠️ 为什么这一轮不删**：一次只改一个维度。这一轮的主题是「**把面板能力搬进网页版**」，
再顺手删 997 行就分不清「网页版坏了」是哪一步造成的。

**📌 但注意**：这些不是「垃圾」，是**能力的实现**——
`Thumb` / `ViewControl` / `renderCards` / `renderTable` 代表的正是**网页版该有的那些视图**。
⇒ 下一轮做「网页版补齐」时，**先看这些代码能不能直接搬过去**（比重新写省事，而且已经带了
`onError` 回退、5MB 门槛这些踩过坑的细节），搬完再删。**顺序不能反。**
